# docs/retro

复盘与踩坑沉淀。什么时候写：

- `systematic-debugging` 定位完一个非平凡缺陷后（现象 / 根因 / 为什么没早发现）
- 一次变更超出预估 2 倍以上
- 发现规则本身有漏洞（规则导致了好结果或坏结果，都值得记）

命名：

```
docs/retro/YYYY-MM-DD-<主题>.md
```

模板：

```markdown
# <主题>

- 日期：YYYY-MM-DD
- 关联变更：openspec/changes/<id>

## 现象
## 根因
## 为什么没早发现
## 可复用的教训
## 建议的规则/技能改动
```

**不要**把复盘写成情绪记录；只写能被下一次复用的结论。
