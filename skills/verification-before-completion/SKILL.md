# 技能：verification-before-completion（完成前验证）

## 核心命题

**"完成"是一个可验证的状态，不是一种感觉。**

出现以下表述，说明验证还没做：
「应该可以」「理论上没问题」「逻辑上是对的」「我之前测过类似的」。

## 步骤

### 1. 跑全量验证

```bash
bash scripts/verify.sh
echo "exit=$?"
```

覆盖四个阶段：typecheck → lint → test → build。
顺序不能颠倒：类型错误会让测试结果无意义，构建失败会让测试通过变得没价值。

### 2. 按退出码分流（三态）

| 退出码 | 含义 | 下一步 |
| --- | --- | --- |
| 0 | 至少一个阶段真实执行且全绿 | 可交付 |
| 1 | 有失败项 | 修复后重跑，**不得**改断言/跳过 |
| 2 | **无法验证**（所有阶段被跳过） | 补检查或标注「未验证」，**禁止**说完成 |

退出码 2 是最容易被自欺的一档：脚本"没报错"，但什么都没检查。

### 3. 逐项阅读输出

不要只看最后一行。确认：

- [ ] 每个阶段**真的执行了**，而不是因"无包定义"被跳过
- [ ] 测试数量与预期一致（突然变少 → 有测试没被收集）
- [ ] 没有 skip / only / 被注释掉的用例
- [ ] 没有新增警告（警告是未来的错误）

### 4. 失败归因

| 失败类型 | 处理 |
| --- | --- |
| 环境问题（缺依赖、版本不符） | 修环境，**在汇报中说明** |
| 测试写得不对 | 修测试，但不能削弱它要验证的行为 |
| 实现有缺陷 | 回到 `systematic-debugging` 找根因 |
| 需求本身有问题 | 回到 `brainstorming`，不要硬写代码迁就 |

**禁止的"修复"**：注释掉失败测试、放宽断言、加 `.skip`、关 lint、把严格模式改 false。

### 5. 手动验证不可省略的部分

- 用户可见的界面：真实打开看一眼
- 端到端流程：走一遍完整路径（不只是单点）
- 错误提示：真的触发一次，看文案是否可读、是否泄露内部信息

### 6. 证据落档

写入 `openspec/changes/<id>/verification.md`：

```markdown
# 验证证据 — <change-id>

- 时间：YYYY-MM-DD HH:MM
- 命令：`bash scripts/verify.sh`
- 退出码：0

## 输出摘要
- typecheck  通过
- lint       通过
- test       42 passed, 0 failed
- build      通过

## 手动验证
- 空列表 → 显示空状态文案，无报错
- 超长标题 → 截断显示，不撑破布局

## 未验证项
- 无 / <项 + 原因 + 建议的验证方式>
```

## 无法验证时

明确标注「未验证」+ 原因 + 建议方式：

```markdown
验证：未执行
原因：本机未安装 Docker，集成测试无法启动数据库
建议：在有 Docker 的环境执行 `npm run test:integration`
```

**把「未验证」说成「完成」，是本项目最严重的违规。**

## 退出标准

- [ ] `verify.sh` 退出码 0（不是 2）
- [ ] 手动验证的盲区已覆盖
- [ ] `verification.md` 已写入
- [ ] 汇报中贴的是输出摘要，不是转述
