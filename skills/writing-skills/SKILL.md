# 技能：writing-skills（编写技能）

## 核心认知

**SKILL.md 不是文档，是行为规约。** 判断标准只有一个：
读完它，智能体的行为会变吗？不会 → 它只是废话。

## 文件格式

```
skills/<kebab-name>/SKILL.md
```

```markdown
---
name: <kebab-name>            # 与目录名一致
description: <一句话触发条件 + 不适用场景>   # 决定它会不会被选中
---

# 技能：<name>（中文别名）

## 何时使用 / 不适用
## 核心原则
## 步骤
## 退出标准
## 反模式
```

## 写法要求

1. **description 写触发条件，不写功能简介**
   - 好：`当报错、测试失败、行为与预期不符时使用。禁止靠猜测修改代码。`
   - 差：`这是一个调试技能`
2. **必须有"不适用"**：没有边界的技能会被滥用
3. **必须有退出标准**：checklist 形式，可逐项打勾
4. **必须有反模式**：写你真实踩过的坑，不写通用套话
5. **判据要可检验**：「函数超过 40 行先怀疑」优于「保持函数简短」
6. **不重复规则**：规则只写在 `harness/rules/`，技能里引用即可

## 新增技能前先问

- 现有技能能否覆盖？（能 → 改现有，不要新增）
- 这个套路会重复出现吗？（一次性 → 写进 `docs/retro/`）
- 它的判据是可检验的吗？（不能 → 还没想清楚）

## 改完必须做的事

1. 在 `AGENTS.md` 第 5 节「技能索引」表里登记（否则不会被发现）
2. 在 `skills/using-skills/SKILL.md` 的链路表里更新（如涉及新链路）
3. 检查是否与 `harness/rules/` 冲突（冲突 → 以规则为准）

## 退出标准

- [ ] frontmatter 的 `name` 与目录名一致
- [ ] description 含触发条件 + 不适用
- [ ] 有步骤、退出标准、反模式三段
- [ ] 已登记到 `AGENTS.md` 技能索引
- [ ] 与现有技能无职责重叠（或已合并）

## 反模式

- 写成教程/科普，没有可执行判据
- description 只写"用于 XX"，导致永远不被触发
- 一个技能塞三种任务（应该拆开）
- 新增技能后不登记索引，等于没写
