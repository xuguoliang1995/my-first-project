# 10 — 代码规范

技术栈未定，因此这里只约束**与框架无关**的部分。栈确定后在此追加框架专属章节。

## 分层边界

| 层 | 允许依赖 | 禁止依赖 |
| --- | --- | --- |
| `apps/*` 的 UI 层 | `packages/shared` 的类型与纯函数 | 直接访问数据库 / 文件系统 |
| `apps/*` 的业务层 | 领域模型、`packages/shared` | UI 组件、HTTP 请求细节 |
| `apps/*` 的接口层 | 业务层、共享类型 | 跨层调用业务层内部实现 |
| `packages/shared` | 无外部业务依赖 | 任何 `apps/*`、任何 I/O |

判据：**`packages/shared` 里出现 `fetch`、`fs`、`window`、`process` 就是越界。**

## 命名

- 文件：`kebab-case.ts`；导出的组件/类型：`PascalCase`；函数与变量：`camelCase`
- 布尔值用 `is` / `has` / `can` / `should` 前缀，不用 `flag`、`status` 这类模糊词
- 常量全大写下划线：`MAX_RETRY_COUNT`
- 禁止缩写除公认的以外（`id`、`url`、`http` 可，`usr`、`cfg`、`btn` 不可）

## 函数

- 单一职责：一个函数只做一件事，超过 40 行先怀疑要不要拆
- 参数超过 3 个改用对象；布尔参数不超过 1 个（否则调用处不可读）
- 早返回优于深层嵌套，嵌套超过 3 层必须重构
- 纯函数优先：不修改入参，副作用集中在边界层

## 错误处理

- **禁止吞掉错误**：`catch {}` 是缺陷，不是简洁
- 错误信息必须包含**做了什么 + 期望什么 + 实际什么**
- 面向用户的错误不暴露内部细节（堆栈、SQL、路径）
- 可预期的失败用返回值表达，不可预期的用异常表达
- 共享的响应契约统一用 `packages/shared` 的 `ApiResult<T>` / `ApiError`

## 类型

- 禁止 `any`。确实未知用 `unknown` + 类型收窄
- 禁止 `as` 强转绕过类型检查，用类型守卫
- 领域模型从 `packages/shared` 复用，不重复定义

## 注释

- 注释解释**为什么**，不解释**是什么**
- 每个文件顶部一句话说明职责
- 临时方案必须写 `TODO(变更id): 原因与移除条件`
- 不写无信息量的注释：`// 循环`、`// 返回结果`
